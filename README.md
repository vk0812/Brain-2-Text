`data/raw/` contains local BOLD5000 stimulus images, metadata, and GLMsingle ROI beta files. The full `Presented_Stimuli` scene image directory currently contains **4,916 images**. `BOLD5000_Stimuli_samples/Presented_Stimuli/` is a small sample directory with four images.

The CSI1 trial image manifest in `outputs/bold5000/` has **5,254 presentation rows** (plus its header) and records trial identifiers, image names, repetition information, event-file references, and available image paths.

The notebook explores the BOLD5000 data and the relationship between CSI1 image presentations, event rows, and ROI response rows. The cheatsheets contain dataset notes and reference material for neuroscience and imaging concepts.

## Python environment

The project requires Python 3.12. Dependencies are declared in `pyproject.toml` and pinned in `uv.lock`.

```bash
uv sync
```

The embedding scripts use PyTorch, Transformers, NumPy, and Pillow. On first use, Transformers downloads the selected pretrained model from Hugging Face. Device selection prefers Apple MPS, then CUDA, then CPU.

## Source scripts

| File | Current contents |
| --- | --- |
| `src/extract_embeddings.py` | Configurable batched image embedding extraction for CLIP ViT-B/32 and DINOv2-Large. Saves an `.npy` feature matrix and a matching CSV image index. |
| `src/test_embeddings.py` | Checks saved matrices and mappings against the image directory, validates normalized finite vectors, and re-embeds a seeded random sample to check row alignment. |
| `src/preprocess_fmri.py` | Concatenates the 10 ROI beta files of a subject, builds the trial table from the presentation lists, z-scores each voxel within each session, and checks trial alignment. |
| `src/models.py` | PyTorch MLP (voxels → 1024 → embedding) trained with either a cosine loss or a symmetric contrastive (InfoNCE) loss. |
| `src/train.py` | Image-identity train/val/test split, hyperparameter selection on val, refit on train + val, single test evaluation. Models: `ridge`, `mlp` (cosine loss), `mlp_infonce` (contrastive loss). |
| `src/evaluate.py` | Cosine-similarity retrieval ranks, Recall@1/5, median rank, 2-way identification, and chance levels. |
| `src/noise_ceiling.py` | Brain-to-brain identification of repeated images (single-trial signal reference); writes `outputs/noise_ceiling.json`. |
| `src/summarize_results.py` | Aggregates `outputs/results/*.json` into a mean ± std Markdown table over seeds. |

## Image embeddings

The generated matrices are stored under `data/processed/embeddings/`. Each matrix is `float32`, L2-normalized, and ordered according to its corresponding index CSV. The index has one row per embedding, with columns `embedding_index`, `filename`, and `relative_path`.

| Model key | Hugging Face model | Embedding file | Shape | Index file | Approx. size |
| --- | --- | --- | --- | --- | --- |
| `clip_vit_b32` | `openai/clip-vit-base-patch32` | `clip_vit_b32.npy` | `(4916, 512)` | `clip_vit_b32_index.csv` | 9.6 MB + 291 KB |
| `dinov2_large` | `facebook/dinov2-large` | `dinov2_large.npy` | `(4916, 1024)` | `dinov2_large_index.csv` | 19 MB + 291 KB |

CLIP embeddings use the vision model's pooled output followed by CLIP's visual projection. DINOv2 embeddings use the final hidden state's CLS token. Both are L2-normalized. The CSV paths are relative to the presented-stimuli image directory.

Load a matrix and its row mapping with:

```python
import csv
import numpy as np

embeddings = np.load("data/processed/embeddings/dinov2_large.npy")
with open(
    "data/processed/embeddings/dinov2_large_index.csv",
    newline="",
    encoding="utf-8",
) as file:
    image_index = list(csv.DictReader(file))

# embeddings[i] corresponds to image_index[i]["relative_path"]
```

## Running embedding scripts

Extract embeddings for one model:

```bash
uv run python src/extract_embeddings.py --model clip_vit_b32
uv run python src/extract_embeddings.py --model dinov2_large
```

Run both models:

```bash
uv run python src/extract_embeddings.py --model all
```

The default model is `clip_vit_b32`. `--batch-size` controls inference batch size; `--image-dir` and `--output-dir` override the default paths. `--limit N` processes only the first N images in sorted path order. Use a separate output directory for a limited smoke run so it does not replace the full-dataset outputs:

```bash
uv run python src/extract_embeddings.py \
  --model dinov2_large \
  --limit 8 \
  --output-dir outputs/embedding_smoke_test
```

Verify both full-dataset embedding stores and re-infer eight deterministic random images per model:

```bash
uv run python src/test_embeddings.py --model all --samples 8 --seed 42
```

The verifier checks that each index exactly matches the sorted image list, row indices are sequential, embeddings are finite and normalized, and sampled re-inference agrees with the saved vectors.

## fMRI preprocessing

Input: the GLMsingle ROI betas in `data/raw/BOLD5000_GLMsingle_ROI_betas/py/` (TYPED-FITHRF-GLMDENOISE-RR, 5 visual ROIs × 2 hemispheres) and the official presentation lists in `BOLD5000_Stimuli/Stimuli_Presentation_Lists/`. The stimuli archive may be extracted under `data/raw/bold5000/` or `data/raw/bold5000/stimuli/`; both are accepted.

```bash
uv run python src/preprocess_fmri.py --subject CSI1   # CSI1–CSI4
```

Outputs in `data/processed/fmri/` (not tracked by git):

| Subject | Matrix `<subject>_roi.npy` | Unique images | Repeat correlation (shuffled) |
| --- | --- | --- | --- |
| CSI1 | `(5254, 1685)` | 4916 | 0.093 (0.000) |
| CSI2 | `(5254, 1228)` | 4916 | 0.060 (0.000) |
| CSI3 | `(5254, 1576)` | 4916 | 0.077 (0.004) |
| CSI4 | `(3108, 2787)` | 2952 | 0.074 (0.015) |

`<subject>_trials.csv` has one row per matrix row: `row, session, run, trial, filename, is_rep`.

Decisions and checks:

- **Trial alignment.** Rows are ordered by session, run and trial number taken from the presentation-list file names (`CSI_sessXX_runYY.txt`, one image per line). This was verified from the data itself: trials that showed the same image correlate (0.06–0.09) under this ordering and ≈ 0 under a shuffled ordering. The script fails if this check does not pass.
- **`rep_` prefix.** Repeated presentations are written `rep_<filename>` in the lists; the prefix is stripped and kept as the `is_rep` column.
- **Per-session z-scoring.** Each voxel is standardised within each session (as recommended by the BOLD5000 documentation), removing day-to-day baseline and scale differences.
- **ROI naming.** CSI2/CSI3 name LOC as `LO` and one file is spelled `RRSC`; the script handles both.

## Experiments

```bash
uv run python src/train.py --model ridge --subject CSI1 --embedding clip_vit_b32 --seed 0
uv run python src/train.py --model mlp   --subject CSI1 --embedding dinov2_large --seed 0
uv run python src/train.py --model mlp_infonce --subject CSI1 --embedding clip_vit_b32 --seed 0
uv run python src/summarize_results.py
```

Protocol (identical for every model):

1. **Split by image identity, not by trial.** 80 / 10 / 10 % of the unique images go to train / val / test; all presentations of an image stay in the same split, so repeated presentations cannot leak. `ImageNet/n03017168_3695.JPEG` and `ImageNet/n03447721_2079.JPEG` are byte-identical and treated as one image.
2. **Hyperparameters chosen on val** by median retrieval rank:
   - ridge: α ∈ {10, …, 10⁵}
   - `mlp`: weight decay ∈ {0.01, 0.1, 1} and number of epochs (checked every 5, up to 60)
   - `mlp_infonce`: temperature τ ∈ {0.01, 0.03, 0.1} and number of epochs (weight decay fixed at 0.1)
3. **Refit on train + val**, then evaluate **once** on the test images.
4. **Retrieval:** each test trial is a query; the gallery is the embeddings of the test images (≈ 492 for CSI1–3, 295 for CSI4); candidates are ranked by cosine similarity. Image embeddings are looked up by filename, never by row position. Metrics: Recall@1, Recall@5, median rank, and **2-way identification** (the fraction of wrong candidates scored below the correct one; 50 % = chance). 2-way barely depends on gallery size, so it is the metric used to compare galleries of different sizes.
5. Results are saved to `outputs/results/<model>_<subject>_<embedding>_seed<seed>.json` and reported as mean ± std over seeds 0–4 (each seed is a different split).

Observations:

- Every configuration is well above chance (median rank 18–108 vs. 148–246).
- **Contrastive loss is the largest improvement so far.** `mlp_infonce` beats the cosine-loss `mlp` on every metric in all 8 subject × embedding settings, well beyond one standard deviation. With CLIP, median rank roughly halves (CSI1: 47 → 19, CSI2: 73 → 39, CSI3: 66 → 30, CSI4: 37 → 18) and Recall@5 rises 1.7–2.4×. The cosine loss only pulls each prediction towards its target; InfoNCE explicitly ranks the correct image above the other images in the batch, which is what retrieval measures.
- **MLP vs. ridge (both regression losses).** The cosine MLP has a better median rank than ridge in all 8 settings (by 4–16 ranks); Recall@1 differences are mostly within one standard deviation. A nonlinear mapping alone helps only modestly.
- **CLIP vs. DINOv2.** CLIP embeddings are easier to predict than DINOv2-Large ones for all subjects and models, and the gap widens with the contrastive loss (CSI1 median rank 19 vs. 49). The two encoders differ in size and dimension (512 vs. 1024) as well as in training objective, so this is not yet a clean comparison of objectives.
- **Subjects.** Among CSI1–3, CSI1 decodes best and CSI2 (fewest ROI voxels: 1228, weakest repeat correlation) worst. CSI4 is not comparable because of its smaller gallery.
- **Hyperparameters.**
  - Cosine MLP: the selected weight decay varies without a pattern.
  - InfoNCE MLP: CLIP mostly selects τ = 0.03, DINOv2 mostly τ = 0.1.
  - **34 of 40 InfoNCE runs select 5 epochs, the earliest checkpoint**, so the best stopping point may be earlier. Checking every epoch (or lowering the learning rate) is a cheap next experiment.
- Most test queries are single presentations (≈ 4800 of 4916 images are shown once), so these numbers reflect single-trial decoding.

## Brain-to-brain identification (noise-ceiling reference)

```bash
uv run python src/noise_ceiling.py   # writes outputs/noise_ceiling.json
```

How identifiable is a single fMRI trial by itself, without any image model? For every image shown several times, one presentation is the query, and the task is to find the same image's other presentation(s) among those of all repeated images, by Pearson correlation of the voxel patterns.

- **single**: each gallery item is one other presentation (noise on both sides).
- **averaged**: each gallery item is the mean of 3 other presentations (less noise on the gallery side, closer to the decoder, whose targets are noise-free embeddings).

| Subject | Brain-to-brain, single: 2-way (%) | Brain-to-brain, averaged: 2-way (%) | Ridge (CLIP): 2-way (%) | InfoNCE MLP (CLIP): 2-way (%) |
| --- | --- | --- | --- | --- |
| CSI1 | 80.6 | 86.9 | 78.9 ± 1.0 | **92.0 ± 0.6** |
| CSI2 | 64.8 | 71.6 | 73.9 ± 0.4 | **86.7 ± 0.7** |
| CSI3 | 74.0 | 81.1 | 75.5 ± 1.0 | **88.3 ± 0.9** |
| CSI4 | 75.9 | (14 images only) | 77.5 ± 1.2 | **88.5 ± 0.7** |

Brain-to-brain uses ≈ 110 repeated images per subject (90 for CSI4). Its Recall@1 / Recall@5 / median rank are in `outputs/noise_ceiling.json`; e.g. CSI1 single: 11.5 % / 29.6 % / 14 of 114. The decoder columns are the 492-image (CSI4: 295) test galleries from the results table, mean ± std over 5 seeds.

Interpretation:

- **Single-trial signal ranks subjects the same way the decoders do**: CSI1 > CSI3 ≈ CSI4 > CSI2. Subject differences reflect data quality, not modelling.
- **The InfoNCE decoder exceeds the brain-to-brain reference for every subject**, so this measurement is **not** an upper bound on decoding. Two reasons:
  - Plain correlation weights all voxels equally, while a trained decoder learns to emphasise informative voxels and ignore noisy ones.
  - The decoder compares a noisy trial to a noise-free target, while brain-to-brain has noise on both sides.
  - Also, the two are evaluated on different images: the ~110 repeated images vs. random test images.
- A tighter ceiling would need a noise model, e.g. per-voxel split-half reliability with a Spearman–Brown correction, or a learned brain-to-brain metric.
